# Lexora Updates

> Status: Prompt 56 foundation. This document covers app-update signing and the local/test content-update manifest used before the full package updater.

## App Updater

Lexora uses the Tauri 2 updater foundation.

- `src-tauri/tauri.conf.json` enables `bundle.createUpdaterArtifacts`.
- `src-tauri/src/lib.rs` registers `tauri-plugin-updater`.
- `check_app_update` reads updater settings from environment variables. No production release URL is hardcoded in source.

Required environment variables for live checks:

- `LEXORA_UPDATE_ENDPOINT`: Tauri updater endpoint or static `latest.json` URL. Production endpoints must use HTTPS.
- `LEXORA_UPDATE_PUBLIC_KEY`: public key generated by the Tauri signer. This is public metadata, but it must match the private key used in release CI.

Local/test checks:

- Settings uses test mode in development builds.
- `LEXORA_TEST_APP_UPDATE_VERSION` can simulate a newer version. If unset, test mode reports the current version as up to date.

## Signing Requirements

Tauri updater artifacts must be signed. Release CI must:

1. Generate a key pair once with `pnpm tauri signer generate -w <secure-key-path>`.
2. Store the private key and password outside the repository.
3. Set `TAURI_SIGNING_PRIVATE_KEY` before `tauri build`. The value may be the private key content or a path available to CI.
4. Set `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` if the private key is encrypted.
5. Publish the installer/updater artifacts and `.sig` files together.
6. Publish a static `latest.json` or dynamic endpoint response that includes version, URL, and signature.

The private key must never be committed. Losing it prevents future updates for already installed apps.

## Content Manifest

Content updates are separate from app binary updates.

- Schema: `apps/desktop/src-tauri/content-updates/manifest.schema.json`
- Test manifest: `apps/desktop/src-tauri/content-updates/test-manifest.json`
- Runtime override: `LEXORA_CONTENT_UPDATE_MANIFEST`

The manifest supports these package kinds:

- `seed_db`
- `data_patch`
- `catalog`
- `asset`
- `audio`

Audio package rules:

- Audio packages must be `optional: true`.
- Audio packages must be `required: false`.
- Audio packages must use `downloadPolicy: "manual"`.
- Required package byte counts exclude optional audio, so update checks never force large audio downloads.

The Prompt 56 service only checks and summarizes manifests. It does not download, unpack, apply, or delete packages; that belongs to the later content package update prompt.
